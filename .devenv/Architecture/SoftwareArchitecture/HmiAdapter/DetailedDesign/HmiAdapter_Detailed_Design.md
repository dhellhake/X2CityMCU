# DD-001 — Software unit design: HmiAdapter

## Caller supplied execution time

Invocation timing follows the canonical caller supplied `ExecutionTime` contract in [Runtime Integration Contract](../../Runtime_Integration_Contract.md). Component-specific age, expiry and timeout ownership remains defined by each unit contract.


### U-HMI-ADAPTER

The HMI adapter distinguishes a current qualified level/speed receipt from decoder initialization, retained setting and transport activity. Each request's `receiptTimeMicroseconds` is the validated-frame receipt time in the caller-supplied host-boot monotonic microsecond domain; it is source receipt time, not a battery or motor measurement time. A new valid frame refreshes this time even when its values are unchanged. Invalid frames, cached-record republication and qualification-only updates do not refresh it; before the first valid frame it is unusable under qualification. Endpoint loss, restart or unqualified receipt creates no setting or authority. It receives Session's already-selected fault/no-error indication, qualified actual SOC, signed pack current and qualified Traction motion, then forms protocol bytes while retaining each source qualification and context. For qualified actual SOC s in percent, usable display SOC is clamp(100 × (s − 10) / 70, 0, 100), mapping 10% to empty and 80% to full. The speed/period fields use only the existing `QualifiedMotion.vehicleSpeedKilometresPerHour`, `travelDirection` and `standstill` evidence; unresolved status bits, invalid speed and timing use the existing encoding gates. Transmission does not prove display receipt. Encoding, rounding, timing, electrical transport and display presentation remain gates; the physical five-pin interface, pin conditioning and hardware wake path remain outside SC-HMI. The current Draft System allocation separately assigns interpretation of qualified `HmiPowerLockObservation` into `VehicleOperationRequest` to HmiInformationProcessing; detailed software port/unit mapping remains later refinement.
