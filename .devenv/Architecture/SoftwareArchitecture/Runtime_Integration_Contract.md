# Vehicle runtime integration contract

**Draft 0.2 — 2026-09-16.** This is the implementation-facing design contract for the selected vehicle sensor and traction realization. It refines ARCH-003, DD-001–004 and the [traction HSI](../DRV8300DRGE-EVM/DRV8300DRGE-EVM_WeAct_STM32H723VGT6_Traction_HSI.md). It is not firmware evidence or an allocation of the independent hardware inhibit.

## Boundary and current implementation status

A binding is project-owned code that selects a resource, static rank/trigger setup, vector and data route. A generic driver operation is project-independent register access. Current Rust sources do not implement the selected ADC, TIM/PWM, DMA, EXTI or NVIC bindings, nor a safe DMA storage abstraction. The planned bindings therefore do not describe delivered driver capability. The current cyclic OS has 1/5/10/20/50/100-ms releases; vehicle deployment uses 5 and 10 ms, and has no DMA-to-task wakeup API. A 10-ms cyclic qualifier is the nominal interface period, while its WCET, capacity and freshness limits remain qualification values. The regular 1-kHz rate is a planned target only; its timer/trigger, jitter and ADC1/ADC2 rank identities are preimplementation derivation and readback gates.

## Canonical caller supplied execution time

Every project software component invocation receives the typed input `ExecutionTime(currentTimeMicroseconds:Integer)`. `currentTimeMicroseconds` is sampled from the shared monotonic host clock immediately before that invocation by its caller, then remains fixed for the invocation; it is never the planned task release timestamp or one task-start snapshot reused after an unbounded delay. The caller supplies the same reference to direct and interrupt fast callers without introducing a queue or scheduler. Each component uses the supplied current time for its own age, expiry and timeout decisions, and keeps any timeout supervision state private. WCET and elapsed margin evidence must bound the interval represented by the fixed input.

When a component implementation dispatches bounded internal leaves as part of that one invocation, those leaves may inherit the same fixed `ExecutionTime`; a new component or standalone-unit invocation requires a new caller sample. Guards retain the conservative maximum elapsed interval from the invocation snapshot through the relevant use/effect, including literal timer guards.

This timing input is a call argument dependency, not a queued time stream and does not create a clock-provider component or Platform broadcast. The current `src/os` cyclic path still passes its planned `task.timestamp_us` to callbacks; that is a current-code limitation and does not satisfy this contract. A future calling-task adapter/binding shall obtain live `GetElapsedMicroseconds` immediately before dispatch and pass it to the component. Acquisition and event capture preserve their actual source timing (and known offset); receipt time never retimestamps earlier evidence. Native capture counters remain internal and are converted at the acquisition boundary when a qualified common-domain timestamp is required.

### Battery supervision and publication delivery

The implemented BmsLink profile uses the SP14S004 V1.0 read protocol with owner-reported firmware 3.2; firmware 3.2 is device identity evidence, not a protocol version. On every normal or unexpected host startup, exactly two private startup checks must both pass in the current startup's accepted `0x03` reply before dependent outputs qualify: firmware version 3.2 and reported series-group count 14. Decode firmware with the evidence-qualified installed-unit encoding; do not assume a raw byte, offset or payload length. Missing, invalid or mismatching either check leaves dependent BmsLink observations unqualified; BatteryProtection then publishes zero effective current for unqualified dependent limits. Startup qualification adds no public flag or port. Runtime `0x05` identity remains informational only and is neither a startup block nor an order prerequisite. Hardware V1.0, model and configuration acceptance remain commissioning evidence. Fixed command-schema length, field-count and encoding checks continue for every response. Same-response scale, NTC/probe validity and complete fourteen-group data are normal observation qualifications, not more dedicated startup checks. Payload mappings and accepted lengths remain engineering evidence to capture and verify.

Battery voltage-derating thresholds are compiled product-validation data owned by BatteryProtection and checked during startup self-test against finite-positive/order and compiled-configuration identity rules. Their selection/refinement remains product validation; changing them requires rebuild, deployment and restart. This does not change BmsLink startup qualification, which remains exactly firmware version 3.2 and reported group count 14.

`BmsLink` checks its private per-source/per-field accepted-update timers on every normal invocation, including invocations without an accepted decoder frame. They bound host elapsed time since the last accepted matching response and include conservative remote-update-latency/source-validity uncertainty; they do not represent a remote BMS sample time or prove its sampling interval. Only a frame-valid response accepted for the current request and then decoded for a matching field refreshes that source field; same-value accepted updates count. Generic frame integrity checks boundaries, declared/received length consistency within protocol bounds, and checksum independently of payload content or command schema. A valid wrong-command or error-status response is a transaction outcome, not a malformed frame, and refreshes no source field; per-command count/encoding/shape failures belong to decoding. Malformed/cached data, qualification-only snapshots and transaction timeouts also refresh no source field. Expiry withdraws the affected qualification and is published even when no new response arrived. A transport reply timeout alone does not expire still-within-bound field evidence. `BatteryProtection` checks a private BmsLink-publication watchdog even when no publication is delivered and withdraws affected battery qualification/limits on expiry. SessionEligibility and Demand each maintain independent private watchdogs for the BatteryProtection operating-limits and actual-SOC publications they consume; HMI independently watches actual SOC and signed current. Demand's SOC watchdog is separate from its operating-limits watchdog and both are separate from BmsLink source-age timers. A new unchanged snapshot may renew only that stream's delivery liveness, never underlying BMS source qualification. Host/consumer startup or reset clears usability of prior snapshots and timer history; reset does not itself begin a valid watchdog window. Bounded resynchronization and a current post-resync publication are required before delivery liveness is established. Source-timeout qualification loss follows the existing required-information and reason/fault rules, including existing BatteryFaultStatus recognition order. Consumers receive values plus field qualification only and make no source-age calculation from a payload timestamp.

`U-BAT-POLICY-EVALUATE` owns one private startup nominal-capacity reference shared by charge and discharge assessment. It captures the same qualified finite positive `reportedNominalCapacityAmpereHours` once at normal or unexpected vehicle-controller startup and retains C for the complete cycle. Later readings, field qualification or availability loss/expiry, and context changes do not reset, re-recognize, or reacquire C. A new controller startup begins a new cycle and captures that cycle's reference; no prior-cycle value is restored. Both regenerative and discharge base currents derive from this one cache. It remains distinct from live BmsLink field qualification and adds no public startup, freshness, timestamp, or capacity-cache port.

The existing intercom `Some`/`None` dequeue and lost-count indication do not timestamp a message or bound its queue delay. Before battery data uses that transport, runtime integration must provide a bounded service/drain policy and a current-snapshot route, prove a maximum queue/delivery/use delay within the conservative source-validity/update/detection margin, and define startup/reset resynchronization: invalidate the consumer snapshot, drain/discard queued items to `None` under a bounded producer/service boundary, and only then acquire the next publication through the current-snapshot route or accept the next bounded post-drain publication. The consumer remains invalid until that post-drain handoff; it cannot treat reset as a new valid timeout window. An arbitrarily delayed queued item cannot restore liveness. Queue capacity alone is not a time bound. Per-field source-age and source-update-uncertainty, BMS transaction response, startup/requalification, producer and consumer publication-delivery watchdog, scheduling, transport, use/effect and end-to-end margin values are explicit engineering gates to derive and accept; no timestamp or sequence is added to battery payloads to compensate for an unbounded delivery path.

`U-SESSION-REPORT` receives the existing BatteryProtection operating-limits assessment and actual-SOC streams directly as typed records. It maintains separate private delivery watchdogs for each stream using caller-supplied `ExecutionTime`; no public timestamps are added. The MOS-state watchdog is independent of common/current-limit branch qualification. Qualified MOS true activates the warning cause, qualified false clears it, and stale/unqualified delivery withdraws MOS-warning evidence without implying MOS enabled or retaining stale `0x01`; the existing required-information/fault policy applies. Current qualified SOC at/below 10% activates its independent low-SOC cause, which clears only above 10%. The composed warning remains below a selected retained group fault. Neither report selection nor Demand infers MOS state from zero current allowance.

## Ownership and direct fast chain

| Owner | Binding or direct operation | Output / rule |
|---|---|---|
| `U-PLATFORM-CONTEXT` / `U-PLATFORM-BINDING` | `B-PLATFORM-BOOT`, `B-PLATFORM-IRQ-DISPATCH` | Static clocks, ADC ranks/triggers, DMA/D2 non-cacheable attributes, vectors, priorities and resource ownership. It dispatches only. |
| `U-ANALOG-ACQ-FAST` / SC-ANALOG-ACQ | `B-FAST-ANALOG-JEOS` | Bounded ADC1/ADC2 JEOS/JDR1/JDR2 snapshot into raw `InjectedEpoch`. No DMA, task wakeup, queue, allocation, logging or unbounded lock. |
| `U-MOTOR-PHASE-FAST` / SC-MOTOR-PHASE-IF | direct fast call | Calibrates/scales current codes, checks aperture/window/range, reconstructs only from the admissible same-epoch pair and publishes immutable phase feedback. |
| `U-SUPPLY-FAST` / SC-SUPPLY-IF | direct fast call | Calibrates rank-2 `SEN_PVDD` into `FastDcLinkVoltageRecord`; it carries its actual rank-2 timestamp/skew and is not asserted simultaneous with the current pair. |
| `U-HALL-POSITION` / SC-HALL-IF | direct nonqueued accessor | Returns current qualified Hall observation (code, map/alignment sector bounds, transition direction/time) or unavailable; it never returns final electrical angle. |
| `U-MOTOR-POSITION-ESTIMATOR` / SC-MOTOR-POSITION-ESTIMATOR | bounded direct fast call and disarmed/startup qualification call | Produces one final `MotorPositionRecord(Position, Qualification)` from mandatory Hall observation for TractionControl, RidingControl and Platform; phase current and qualified applied voltage assist only when observable. Qualification remains delivered for fault supervision when Position is unavailable and does not refresh the Position reference time. The startup call runs before Ready without authority, PWM, current, voltage or standstill prerequisites. |
| `U-TRACTION-CONTROL` / SC-TRACTION-CTRL | direct fast call | Accepts authority/command and the qualified phase, fast-Vdc and electrical-position inputs; executes FOC and produces next `CCR1..3`, `CCR4` and ADC context. |
| `U-TRACTION-OUTPUT` / SC-TRACTION-CTRL | direct fast call | Sole literal writer of `CCR1..4` and JSQR; performs the HSI guarded stage/commit transaction. |

The active chain is `JEOS → raw injected epoch → phase feedback + fast Vdc`, while Hall observation and qualified applied voltage enter `U-MOTOR-POSITION-ESTIMATOR`, then final position enters FOC before output. It runs in the fast interrupt context and is outside scheduler and intercom. A separate bounded disarmed/startup estimator invocation uses caller-supplied time and Hall observation without waiting for JEOS, authority, PWM, current/voltage assistance or qualified standstill. `U-TRACTION-CONTROL` orchestrates FOC but has no sensor-calibration, DMA, Hall-capture or direct compare ownership. `U-TRACTION-OUTPUT` alone dynamically writes `CCR1..4` and JSQR. Static peripheral/rank/trigger configuration belongs to `U-PLATFORM-BINDING`.

## Fast access, safety and fixed-build parameters

All active JEOS, output and software-fault access uses the same selected non-nested checked-token discipline. No raw/unchecked alias, nested token, token escape, NMI or HardFault use is permitted for these shared resources. The code must provide a compiler plus hardware completion barrier appropriate to the target; a recheck sequence around unsynchronised shared data is not a safe-Rust publication protocol and cannot replace ownership, atomic acquire/release or a critical section. TIM8 break and the independent hardware inhibit can withdraw permit without OS service, including while configurable IRQs are masked.

`StartupUnqualified` is not a recognised fault. A recognised runtime/recovery fault latches both torque signs inhibited for the operation generation; each sensor health record reaches the existing Session first-recognized-fault/report path without replacement by platform fast-safety state, with AcceleratorInterface carried once in the full `AcceleratorPosition` record and MotorPositionEstimator carried once in the full `MotorPositionRecord` rather than separate health deliveries. A motor-position Qualification-only update remains reliably observable by Session and Platform even when Position is unusable, and does not refresh Position reference time. The independent Platform health/readiness path also remains an input to RidingControl. An unavailable observer-voltage source or weak back-EMF leaves only observer assistance unavailable when the Hall-only estimate meets its bound; it is not a health fault. Accelerator `Qualification` may update without a new ADC sample and remains usable for diagnosis/protection when `Position` is invalid. Only a clean restart creating a fresh operation generation can clear it. Ordinary battery/SOC/temperature restrictions are constraints, not failures. Each applicable component validates its own immutable compiled parameter set during its existing startup/self-test path while permit/MOE remains low. Parameters include raw-acquisition/rank-trigger, current/phase, supply, Hall, position estimator, accelerator, brake and temperature families. A changed parameter set requires rebuild, deployment and restart; its build identity is provenance, not a runtime parameter payload. Acquisition restart and reset still invalidate observations in the normal way.

## Deferred records and DMA lifetime

| Route | Owner and record | Stable delivery / failure rule |
|---|---|---|
| Regular ADC1 | `U-ANALOG-ACQ-REGULAR` → accelerator, brake, temperature, supply-regular and motor-phase-diagnostic interfaces | Each circular completed half has its own generation, completion timestamp and DMA status. ADC1 data are never paired by array position with ADC2. |
| Regular ADC2 | same | Independent sequence and timestamp; a consumer may use a named scan only after its own stability test. |
| Hall captures | `U-HALL-CAPTURE` → `U-HALL-POSITION` | Per-channel completed capture storage, sampled Hall-state association, extended timestamp and overflow/ambiguity status; position owns legal transition/map/direction/alignment acceptance. |

DMA can overwrite memory despite CPU interrupt masking. DMA interrupts perform bounded completion/error bookkeeping only. A consumer selects a completed half only after an `NDTR`/write-window snapshot proves the DMA writer is in the other half; it makes a bounded volatile/raw copy to CPU-owned storage, then verifies that the writer did not enter that half and that status remains clear. The required maximum IRQ/task blocking plus copy time is less than one half recurrence, preventing an undetectable whole-cycle overwrite; otherwise the sample is unavailable. Missed completion, window ambiguity, error, overrun or exhausted consumer capacity also invalidate it. An atomic index alone is insufficient. The active non-cacheable DMA region has no normal Rust mutable reference; its external writes and raw/volatile reads are encapsulated in the binding. A separately CPU-owned snapshot uses correctly synchronised atomic state/acquire-release publication (or a proved lock), never sequence rechecks on ordinary racing fields. There is no assumed current OS intercom endpoint, dynamic registration or DMA task wakeup.

## Required engineering evidence

Before implementation/energisation, measure and validate exact vector/priority ordering, cache/MPU and DMA half ownership, all rank/channel/trigger readback, ADC1/ADC2 regular timestamps, writer-window overwrite/error handling, Hall capture association and complete electrical-position behaviour, compiled-parameter provenance and startup checks, fast JEOS-to-latch WCET and independent inhibit response. The planned nominal regular scan target is 1 kHz; acceptance requires a selected/read-back trigger source, rate/jitter and rank mapping, stated buffer depth, maximum IRQ/task blocking and copy bound, freshness budget, and end-to-end accelerator/brake latency evidence. The separate nominal 10-ms consumer period is likewise not proof. Exact thresholds and every deadline margin remain values to establish.
