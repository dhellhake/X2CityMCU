# DD-002 — Battery protection and BMS software-unit design: BatteryProtection

## Caller supplied execution time

Invocation timing follows the canonical caller supplied `ExecutionTime` contract in [Runtime Integration Contract](../../Runtime_Integration_Contract.md). Component-specific age, expiry and timeout ownership remains defined by each unit contract.


## SC-BAT-POLICY

### Units, interfaces and executable order

`U-BAT-POLICY-EVALUATE` consumes typed qualified battery measurements, compiled pack constraints, BmsLink's decoded field qualifications and local operating context through `SW-I-003`/`SW-I-009`. `SC-BAT-POLICY.V` owns the compiled `BatteryVoltageDeratingCalibration` set, structurally bound to the one canonical `BatterySupervision.voltageDeratingCalibration` source; the evaluator references the same set and the owner's existing `compiledBatteryConfigurationId`/`compiledBatteryConfigurationValid` identity. It adds no runtime input. The four values are product-selected and refined through validation; they are compiled and checked in startup self-test. Changing them requires rebuild, deployment and restart. This is a host configuration check and does not add a BMS compatibility check. It also owns the single private startup nominal-capacity reference shared by regenerative-charge and discharge calculations, as specified below. BmsLink's private startup qualification is reflected through dependent field qualifications. BatteryProtection consumes only qualified observations/source evidence and does not inspect raw BMS fields; a required unqualified input leaves each dependent branch unqualified with effective current zero. Regular scale, complete-group, NTC/probe, protection, and temperature qualifications remain observation inputs. It checks its private BatteryMeasurements-delivery watchdog on every normal invocation, even without a new snapshot. A current field-qualified snapshot renews only this consumer watchdog, including when values are unchanged; it does not renew BmsLink source qualification. Watchdog expiry makes the affected inputs unavailable and withdraws every dependent branch qualification/current allowance. It constructs independent charge and discharge capability candidates with finite non-negative effective current limits and reason sets. Applicable shared checks are assessed internally and included in each dependent branch qualification; the public `BatteryOperatingLimitsAssessment` has no separate common-validity flag. Branch-specific missing evidence withdraws only that branch, while loss of a required shared input withdraws every dependent branch. The per-consumer input subset, required temperature channels, numeric plausibility limits and timeout criteria remain open; this contract does not presume that current is mandatory for both branches. Independently, it publishes `BatteryOperatingLimitsAssessment.mosDisabledState` from current qualified charge- and discharge-MOS source states: the qualified value is true when either is disabled and false only when both are enabled. Unknown, invalid or stale path source state makes this MOS status unqualified independently of the branch qualifications. A qualified charge-path OFF state makes regenerative-charge current zero; a qualified discharge-path OFF state makes discharge current zero. The OFF branch remains qualified when all other applicable shared and branch checks pass; required unknown/invalid shared path state leaves every dependent branch unqualified and current zero. ON removes only the path restriction and does not prove positive capability. OFF status alone does not establish a fault or physical isolation; recognized faults remain reported under existing rules. A missing required input leaves each dependent branch unqualified and its effective current limit zero; a qualified zero remains valid known capability. `BatteryOperatingLimitsAssessment` carries only branch qualification and source context to Session Eligibility and Demand, with no timestamp. `BatteryFaultStatus` independently retains all recognized battery/thermal fault evidence and ordering even when operating limits are unqualified. It applies the most restrictive available qualified contribution without using unqualified values. It classifies each cause as a normal restriction or recognized battery fault; it does not infer physical path protection from a reported status.

`U-BAT-POLICY-RESTRICTION` applies operation context to those candidates. It publishes independently qualified electrical discharge and regenerative-charge current limits, reasons, battery-fault evidence, actual SOC and signed current. It does not publish rider wheel-torque or speed ceilings and owns no vehicle positive-propulsion SOC state. BatteryProtection retains voltage, temperature, protection/path, and the approved 90%-actual-SOC regenerative-charge current restrictions. A zero regenerative-charge current is a normal operating restriction, not a battery fault solely because charge capability is zero. RidingControl applies the separate actual-SOC positive-propulsion policy.

The compiled voltage calibration is checked against the owning battery configuration identity/validity. Discharge qualification independently requires its full-current and cutoff thresholds to be finite and positive with cutoff strictly below full-current; regenerative qualification independently requires its full-current and cutoff thresholds to be finite and positive with full-current strictly below cutoff. Apply each voltage taper from its own pair. A failed pair check leaves only its dependent branch unqualified with effective current zero; the opposite branch retains independent assessment. A valid formula yielding zero remains qualified known capability. The values are selected and refined by product validation and are immutable for a deployed build.

The policy evaluation unit owns one private startup nominal-capacity reference shared by regenerative-charge and discharge assessment. It captures the same qualified, finite positive reported nominal capacity C (ampere-hours) once at normal or unexpected vehicle-controller startup and retains it for the complete controller cycle. Live capacity changes, field qualification or availability loss/expiry, and source-context changes do not reset, re-recognize, or reacquire C. A subsequent controller startup begins a new cycle and captures that startup's C. The source is the existing `BatteryMeasurements.socSourceEvidence.reportedNominalCapacityAmpereHours`; BmsLink owns decoding and scaling. Keep `regenerativeBaseCurrentAmperes` and derive the separate `dischargeBaseCurrentAmperes` from the same cached C. The canonical charge and discharge formulas, knots, voltage-factor definitions, clipping, qualification rules, and shared nominal-capacity semantics are specified once in REQ-SYS-BATSUP-007–015. For each qualified branch, publish the exact minimum of the computed pack ceiling and every other applicable qualified battery-side current ceiling or restriction; a qualified disabled/prohibited path contributes zero. A missing or unqualified required applicable constraint leaves that branch unqualified with effective zero, not omitted. With no other lower limit, publish the computed pack ceiling. Existing physical-current envelope, component, path/MOS, SOC, fault, and riding restrictions participate only when applicable; no arbitrary additional derating is permitted. A qualified zero with required inputs qualified is known zero; unavailable required evidence leaves only the dependent branch unqualified with effective zero. T2's central external-probe assignment remains unverified, so cell-temperature source/placement confirmation remains open.

Execution is: invalidate old-context inputs → evaluate availability and candidate causes → update `.V` cutoff state → publish one coherent envelope/reason/fault snapshot. A newly available envelope cannot clear `SC-RIDING-CONTROL` inhibition, authorize torque, or bypass the distinct regeneration acceptance conditions.

### State, reset and invariants

Envelope snapshots are volatile and vehicle-context-tagged. RidingControl consumes qualified actual SOC for its positive-propulsion eligibility boundary; BatteryProtection does not own that vehicle-level policy. No battery-fault history is retained.

Invariants: no unknown required input enlarges an effective current limit; charge and discharge remain distinct; every published restriction identifies its operation; a qualified zero capability is valid and not a fault; a restriction is not reported as a fault; and software policy output is not physical current limitation or protection evidence.

### Acceptance scenarios

Exercise independent loss/recovery of required BMS measurement/configuration evidence; single shared C capture at normal and unexpected controller startup; later capacity readings and source qualification, availability, expiry, or context changes do not reset or reacquire the cache; the shared reference drives both charge and discharge base currents; missing/invalid/nonpositive startup capacity leaves dependent branches unqualified; and a new startup never restores a previous-cycle value. Verify discharge vectors against REQ-SYS-BATSUP-012–015. Verify compiled voltage-pair finite-positive/order boundaries and identity mismatch under REQ-SYS-BATSUP-016; invalid discharge or regenerative calibration unqualifies only its dependent branch, while a qualified zero from a valid pair remains known capability. Exercise all four charge/discharge path ON/OFF combinations; unknown/invalid shared path state; OFF yielding qualified zero on only the affected branch while the other branch retains its result; ON with another constraint still yielding zero; overlapping SOC/current/temperature causes; normal restriction versus recognized fault; and qualified SOC at, below and above 10% across startup and delivery loss using qualified test abstractions. Verify regenerative ceiling vectors at each temperature breakpoint and linear segment, voltage-factor endpoints and clipping, a pack result selected independently by the lower of thermal and voltage ceilings, physical-envelope/10 A/component caps, SOC at and above 90%, and missing/invalid cell temperature or each of the fourteen group voltages producing unqualified zero. Verify no remaining-capacity or alternate-capacity fallback is used. Verify path status alone neither raises battery fault nor proves isolation, and returning path status alone does not clear the RidingControl fault latch or bypass regeneration recovery guards. System acceptance still must establish numeric current envelopes, source error/age margins, BMS accuracy, probe assignment, protective response.
