# RidingControl software component

`RidingControl.sysml` defines `SC-RIDING-CONTROL`, realizing software-allocated leaf `LE-RIDING`; the [software architecture assembly](../Modelling/X2CitySoftwareArchitecture.sysml) instantiates it as `ridingControlVehicle`. It accepts each shared source record once, internalizes active settings and authority-to-demand exchange, and publishes four separate outputs: riding authority, signed wheel-torque command, selected fault indication and sleep request.

The component contains four stable internal units: [U-SET-STATE](DetailedDesign/USetState.sysml), [U-SESSION-ELIGIBILITY](DetailedDesign/USessionEligibility.sysml), [U-SESSION-REPORT](DetailedDesign/USessionReport.sysml) and [U-DEMAND-ARBITER](DetailedDesign/UDemandArbiter.sysml). Their cohesive behavioral contracts are in [RidingControl detailed design](DetailedDesign/RidingControl_Detailed_Design.md), and their owning decomposition and internal bindings are in [RidingControlDetailedDesign.sysml](DetailedDesign/RidingControlDetailedDesign.sysml). Component ports, execution-time ownership and architecture views are maintained in [ARCH-003](../ARCH-003_Software_Architecture.md) and [DD-003/DD-004](../DetailedDesign/DD-003_Static_Software_Architecture_Views.md).
