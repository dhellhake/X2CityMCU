# RidingControl system component

`LE-RIDING` is the system responsibility for riding control. Its software-allocated leaves are `LE-RIDING-POLICY`, retaining settings, session, authority, reporting, demand and existing abstract software policy, and `LE-CURRENT-CONSUMPTION-COORDINATION`, the sole shared battery-current budget authority. Software realization remains pending. RidingControl receives battery operating limits and qualified pack current and makes them available to the coordinator; battery operating limits also support the existing Ready guards. The coordinator sends independently qualified traction budgets to riding policy for publication with the wheel-torque command. MotorControl enforces these budgets using its qualified average inverter DC-current estimate, not a second pack-current feedback loop. No dynamic auxiliary request/grant protocol is selected.

The [current coordination requirements](Decomposition/CurrentConsumptionCoordination.sysml) allocate a validated worst-case auxiliary reserve for full-bright lights, display, compute, board/conversion consumption, and justified error and transient allowances. Discharge traction budget is `max(0, battery discharge maximum − reserve)`; regenerative charge allocation does not credit auxiliary draw. Qualified pack current supports shared-budget supervision, but its absence alone does not invalidate a qualified capability or reserve-based budget. If auxiliary load alone exceeds discharge capability, zero traction cannot resolve it; existing all-load protection and auxiliary continuity policies apply. Reserve value, measurement error, timing, transient and supervision acceptance remain open.

RidingControl owns the vehicle's [low-SOC propulsion cutoff and recovery policy](Riding_SOC_Requirements.md). It consumes qualified actual SOC from BatteryControl; battery current capability is separate. The architecture allocation and external interfaces are documented in [ARCH-001](../../ARCH-001_System_Architecture.md).
