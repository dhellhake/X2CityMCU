### Qualification evidence and response budget

| Assessment | Minimum evidence to define and obtain |
|---|---|
| Configuration | Recorded 14S5P cell bank, installed BMS/firmware, approved effective protection/capacity/balance configuration, permitted changes and evidence relating readback to that configuration. Separate commissioning evidence from checks repeated at each startup. |
| Observations | Required 14-group voltages, pack voltage, SOC, current and temperature coverage; qualified accuracy, plausible relationships, data age and source availability. Identify each consumer's mandatory subset and shared dependencies; display-only fallback grants no control permission. |
| Protection and paths | Supported protection meanings and expected charge/discharge states per configuration; distinguish reported FET command/status from proven physical transfer or isolation. Establish how detectable path/protection failures are recognized and which failures remain unobservable. |
| Time and margins | Budget source measurement age, polling/transport, qualification/detection, controller action and physical response against the shortest applicable energy/thermal/voltage margin. A fresh reply is not proof of a fresh measurement. Fast electrical protection cannot be justified solely by a slow UART supervision budget. |
| Boundary transfers | Bound residual regenerative charge after inhibition. For example, charge-induced SOC rise is `100 × I_charge,max × t / (3600 × Q_qualified,min)` percentage points; add SOC-estimation uncertainty and other applicable errors. Use qualified capacity/current bounds, not the nominal 16.75 Ah reference as measured capacity. No response time or complete margin is established by this equation. |

The allowed initialization period, measurement-age limit, missing-response/fault recognition and physical reaction budgets need numeric justification before dependent acceptance. Until then, the contract and test cases are defined but timing/coverage is not closed. Software interpretation evidence is in [BMS information](Decomposition/BMS_Information.md#selected-unit-uart-read-acceptance-contract).

### Battery event and recovery matrix

This matrix applies existing vehicle policies to battery evidence; it is not a complete hazard analysis or proof that every listed failure is detectable. A recognized fault's physical response applies regardless of the selected report. All fault-group codes below use existing first-detected/tie selection and restart retention above low-priority `0x01`.

| Qualified event / classification | Riding response and indication | Trace |
|---|---|---|
| Initial required observations/checks incomplete | No Ready or either torque sign; ordinary initial qualification alone creates no fault report. SOC initialization expiry is the established 0x07 fault boundary. | STA-001/005–007; FLT-010; BMS-006 |
| Recognized SOC/UART/battery-information fault affecting required control data | Both-sign fault inhibition; 0x07 for the battery category. Restored data alone does not recover the session. A single rejected reply is not automatically recognized loss; use qualified age/detection criteria. | FLT-005–008; TMP-002; BMS-003/007 |
| Current information unavailable only for HMI, with all control/protection dependencies independently qualified | Transmit 0 A fallback; no new fault solely from that display fallback. If current loss also invalidates required SOC/protection, apply the actual information-fault response above. | DEC-HMI-008; HMI-020–024; BMS-003/007 |
| Normal low SOC ≤20% / reached 10% cutoff | Severe positive torque/speed caps; reached 10% stops positive torque until >20%. Otherwise eligible regeneration and protected auxiliaries remain; 0x01 subject to fault priority. | SYS-SOC-001–009; VEH-PWR-001; ENE-001 |
| Normal regeneration ceiling or valid charge-ineligible temperature | No negative torque beyond available charging capability; positive demand remains otherwise eligible. No dedicated regeneration restriction/fault indication. Apply episode-based recovery after range exit or standstill and clearance. | REG-001/005–007; DEC-REG-003; DEC-TMP-003 |
| Required temperature information fault / actual applicable thermal violation | Both-sign fault inhibition. Known hot/cold violation: 0x06. Battery-domain information failure: 0x07; another information category uses its specific code, otherwise 0x05. Missing temperature alone does not prove a thermal violation. | DEC-FLT-006–008; DEC-TMP-001–003 |
| Expected charge/discharge path disabled for qualified normal state | Apply the known operating restriction; disabled status alone is neither a failure nor proof of isolation. Unknown required readiness blocks dependent permission. | BMS-005/007 |
| Recognized electrical protection intervention or failed protective path, including group OV/UV, overcurrent/short or BMS internal fault | Actual battery fault: both-sign inhibition with 0x07; thermal cause uses 0x06. Cell/group undervoltage protection is distinct from the normal 10% SOC propulsion cutoff. Apply assigned additional energy protection. | DEC-FLT-006–009; BMS-005/007/009; ENE-002–003 |
| BMS reset, sleep/wake or UART return alone | Requalify affected evidence; retain any riding-session inhibition. These events are not a vehicle restart merely because packets resume. | FLT-005–006/011; BMS-005 |
| Normal/unexpected riding-controller restart | Discard old fault history; both signs remain unavailable until fresh self-tests, current observations and complete simultaneous Ready guards pass. New/current faults establish a new session latch. | DEC-STA-001; DEC-FLT-007 |
| Off/fault, accessible contacts or wheel generation with charge path absent | Observe physical current, voltage, energy and unintended torque/drag; zero command alone does not establish a safe energy state. Continue auxiliary functions only where protection permits. | ENE-001–003; BMS-004/009; DEC-FLT-009 |

Rows retain the complete Ready, brake, speed, profile and regenerative-application guards. A common reset spanning several vehicle controllers must satisfy each affected domain's rules; transport restoration cannot silently reset a riding session. Derive exact power/reset-domain evidence in ARCH-001 and the existing open issues.
