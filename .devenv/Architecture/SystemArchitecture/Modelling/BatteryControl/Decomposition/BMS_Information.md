# JBD UART interface definitions

This page records the selected interface's source facts, provenance, and qualification evidence. It is not a second software requirement catalogue: normative software behavior is defined by the BatterySupervision Abstract Software Requirements, especially [REQ-SYS-BMSIF-001..003 and 005..022](BatterySupervision.sysml). Those records own acceptance, rejection, qualification, source-timeliness assessment, retention, recovery, schedule, transaction handling and output timing. BATSUP-001 owns the two per-startup checks (decoded software version 3.2 and reported series-group count 14), both from the same current accepted Basic (`0x03`) response; BATSUP-022 owns the initial startup-evidence deadline and BATSUP-023 the cyclic required-field fault deadline. BMSIF-005–009/015–016 own field/schema decoding and qualification, BMSIF-010 owns source-field expiry, BMSIF-013 owns only the cyclic polling schedule, and BMSIF-020 owns the 10 ms output-publication budget. BATSUP-002–005 own operating-limit qualification, actual-SOC qualification and charge/discharge path capability. `0x05` identity remains informational; physical hardware/model/configuration acceptance is commissioning evidence. The values below describe the manufacturer protocol and remain subject to installed-unit qualification.

## Protocol facts

The selected pack and BMS facts, source hierarchy, and qualification status are maintained in [BAT-001](../../../../../Battery/BAT-001_Selected_Pack_and_BMS.md#fixed-inputs-and-provenance). The owner-confirmed unit is JBD SP14S004 hardware V1.0, firmware version 3.2, using UART. The earlier SP14S004P14S50A designation records provenance for the 14S50A selection, not an alternate device. BAT-001 cites the JBD universal UART protocol V12 as a generic manufacturer reference; the installed firmware version is known, but the fixed firmware-to-protocol mapping and response schemas still require captured installed-unit evidence. Do not infer installed-unit settings or capability from the family datasheet. Firmware version 3.2 is not proof of protocol revision or wire encoding.

### Wire format and source-level decoding facts

| Item | Manufacturer V12 source fact |
|---|---|
| Request frame | `DD A5 command length payload checksum 77` |
| Response frame | `DD command status length payload checksum 77` |
| Checksum | 16-bit two's-complement checksum over command/length/payload in a request and status/length/payload in a response. |
| Byte order | Multibyte values are high-byte first. |

| Read command | Source-described data and format |
|---|---|
| `0x03` basic information | Pack voltage, signed current, capacity/RSOC, reported version, balance/protection/FET status, series count, and temperature fields. Voltage scale is 10 mV. Current sign is positive for charging and negative for discharging. The FET-status scale bit selects 10 mA/10 mAh or 100 mA/100 mAh current/capacity scaling. Temperature conversion is `(raw - 2731) / 10` °C. Layouts and optional extensions depend on the supported firmware form. |
| `0x04` group voltages | High-byte-first group voltage values in mV; 14 groups occupy 28 payload bytes. Values represent the 14 series groups, each containing five parallel cells in the selected pack. |
| `0x05` identification | Device/version identification string. Length, encoding, and extension support require installed-unit evidence. Identity text alone does not describe effective configuration. |

These facts do not establish measurement accuracy, field presence, or applicability to every firmware layout. In particular, group voltage does not observe individual parallel cells. For the selected BMS, the owner confirms exactly three Basic (`0x03`) temperature values ordered MOS, T1, T2; the temperature block precedes checksum/trailer and optional extensions may follow it. The owner confirms T2 is the cell-pack probe placed at pack centre. This selected-unit mapping is not a universal JBD layout; [BMSIF-008](BatterySupervision.sysml) owns decoding and qualification. The family reference's one internal and one external channel remains a family capability description, not complete thermal coverage. Physical roles of MOS/T1, accuracy, coverage, lag, calibration, applicable thermal-trip thresholds and installed wire/schema acceptance remain open; see canonical mapping and evidence limits in [BAT-001](../../../../../Battery/BAT-001_Selected_Pack_and_BMS.md#owner-reported-app-temperature-readings-2026-10-26). Reported RSOC is an observation, not proof of actual SOC.

The generic V12 basic-information FET-status mapping identifies bit 0 as charge-FET status and bit 1 as discharge-FET status; 1 means enabled and 0 means disabled. These are manufacturer protocol facts, not yet accepted decoding semantics for the installed hardware V1.0 / firmware 3.2. They do not prove physical current transfer or isolation. Keep this protocol mapping here; [REQ-SYS-BMSIF-005](BatterySupervision.sysml) requires qualification of the named observations against installed-unit evidence, and [REQ-SYS-BATSUP-004/005](BatterySupervision.sysml) define how qualified states constrain capability.

### Selected polling and timing targets

Owner-selected polling and timing targets, accepted 2026-10-28, are normative in BMSIF-010–022 and BATSUP-001/017/022/023. In brief, `0x03` and `0x04` are cyclic reads and `0x05` is informational; BMSIF-013 owns their schedule, BMSIF-020 the publication budget, BATSUP-022 the startup evidence deadline, and BATSUP-023 required-field fault recognition after startup and during cyclic operation. Transaction acceptance and response timing are defined by BMSIF-014, 018 and 019. These project targets require validation; the protocol does not guarantee internal measurement refresh or response bounds, and host update age is not sample age.

For load estimation, the selected three-NTC Basic base payload is 29 bytes, yielding a 43-byte exchange with its seven-byte request and seven-byte response overhead; the 14-group exchange is 42 bytes. One of each per 200 ms is 85 bytes per pair, or 44.27% line occupancy at 9600 baud, 8N1. Optional extensions may increase occupancy. This arithmetic does not show that response or freshness targets are met. Verification should validate the native requirements against installed-unit behavior and end-to-end source-age/energy/protection budgets.

### Verification guidance

Use the canonical requirements in [BatterySupervision.sysml](BatterySupervision.sysml) as the normative acceptance basis. The following evidence groups are a verification aid, not additional runtime requirements:

| Requirement group | Useful verification evidence |
|---|---|
| `REQ-SYS-BMSIF-003` | T-SW byte-exact response-envelope vectors for complete/unambiguous boundaries, start/end markers, declared versus actual byte length, protocol length bounds, checksum, truncation, and ambiguous concatenated framing. Responses that fail envelope conditions update no measurement and refresh no source timer. T-SYS captures selected-unit exchanges to establish response-envelope behavior. |
| `REQ-SYS-BMSIF-014` | T-SW/T-SYS cases combine envelope conditions with matching versus wrong outstanding requests and success versus non-success response status, including request deadlines. Only a response meeting the envelope conditions, matching the outstanding request, and reporting success may update measurements. A response with a valid envelope and non-success status is a transaction failure; preserve existing failure, timeout, and retention behavior. |
| `REQ-SYS-BMSIF-005..008` | T-SW schema/value vectors for exact per-command payload lengths, field counts, offsets and encoding, signed current and both scale modes, series count, 14 ordered groups, optional fields, temperature conversion, and installed-unit charge/discharge FET-state mapping. T-SYS verifies each field's decoded value, identity, and path-state interpretation against suitable independent references. Also demonstrate that mutually inconsistent but individually valid readings do not invalidate one another and that absent pack voltage does not affect qualification of a complete valid 14-group set. Record physical accuracy, uncertainty, and probe correspondence; independent-reference evidence supports commissioning and verification, not runtime agreement checks between BMS measurements. |
| `REQ-SYS-BMSIF-009..012` | T-SW cases exercise missing/unknown, invalid, and stale field conditions and verify affected fields remain unqualified while unrelated accepted fields retain qualification; specifically, SOC-field-only absence/invalidity/staleness withdraws only `StateOfCharge` qualification without affecting startup, limits, status or fault recognition; pack-current-field-only absence/invalidity/staleness withdraws only the existing `BatteryCurrent` value qualifier and does not change battery operating limits, BatteryStatus, actual SOC, or recognized-fault behavior. Contrast with loss of a whole Basic response or transport, where other fields follow their own age, qualification, and existing fault-recognition rules. Also cover private field timers, accepted same-value updates, unrelated/rejected frames, no-frame timeout, field-level loss, and retained observations. T-SYS covers controller startup/restart, BMS sleep/wake, delayed/missing replies, short communication interruption, source loss, timeout-driven qualification withdrawal and requalification. For the currently shared protection/path-state validity, verify loss or expiry leaves both named path observations unqualified; check published fields against the modeled observation interface and verify internal age/timer supervision drives timely qualification withdrawal. Verify display fallback cannot qualify control data, and requalification does not clear an assigned system fault latch. |
| `REQ-SYS-BATSUP-004/005` | T-SW/T-SYS crosses all four known charge/discharge enabled/disabled combinations, verifying a disabled path produces qualified zero only for its own branch. Verify enabled status leaves all remaining envelope constraints active and does not imply positive capability. Inject unknown/invalid/stale required path-state evidence and verify each dependent branch becomes unqualified at zero. Include recognized-fault cases to confirm existing fault evidence and system response remain effective. |
| `REQ-SYS-BMSIF-013` | T-SYS validates the selected cyclic polling schedule against installed-unit behavior. Measure source sample age, consumer use and physical reaction against energy/protection budgets; distinguish project targets from manufacturer guarantees. |
| `REQ-SYS-BMSIF-020`, `REQ-SYS-BATSUP-022/023` | T-SW/T-SYS measures component output publication and startup/cyclic required-evidence recognition against their separately allocated deadlines, including boundary and delayed/missing-response cases. |

T-SW is software-level vector and boundary verification; T-SYS is selected-unit/system integration evidence. Where appropriate, retain interface, analysis, and fault-injection evidence alongside them. Qualification evidence should include byte-exact exchanges for each implemented read, board/firmware/configuration identity, exact implemented response length/count/encoding, probe count and correspondence, reference instruments and uncertainty, and conditions of capture. A generic protocol example is not selected-unit evidence. Establish the fixed firmware-version-to-supported-schema mapping from accepted captures; do not infer it from version 3.2 or add generic extension discovery.

### Open qualification inputs

The following remain engineering inputs and evidence dependencies, not values specified by this page:

- Captured acceptance of installed board V1.0 and firmware 3.2, effective configuration identity; fixed firmware-to-protocol mapping; supported `0x03`/`0x05` lengths, field counts, offsets, and encodings; and installed wire/schema acceptance, lengths, offsets and encoding for the owner-confirmed three-value MOS/T1/T2 mapping. The selected mapping and T2 centre-probe placement are owner-confirmed; physical MOS/T1 sensor roles are unconfirmed. Board revision may need controlled commissioning evidence if it is not observable over UART.
- UART electrical compatibility and connection arrangement, response behavior, wake/recovery behavior, and whether communication affects sleep or storage consumption.
- Physical measurement accuracy, latency, uncertainty, and probe correspondence for each consumed field. Independent references may establish these engineering properties; runtime field qualification follows the decoded-value and source-timeliness rules in BMSIF-009, without cross-checking reported measurements against one another.
- Validation of the selected cyclic schedule, response/startup/field-age/publication targets and retry behavior; installed-unit internal measurement refresh and response bounds; per-field source sample age and per-consumer freshness criteria; downstream consumer and physical-response bounds; and resulting fitted/detached power budget. Host receipt/update age is not sample age.

Track these under `OI-041/061` and `WS-OI-018/019` with the related BAT-001 qualification inputs.

## Regenerative capability evidence

[REQ-SYS-BATSUP-007–011](BatterySupervision.sysml) use qualified standard nominal full-pack capacity from Basic (`0x03`), the qualified reported cell-temperature reading directly and all fourteen qualified group-voltage readings to assess regenerative pack capability. The voltage input is their maximum; no numerical measurement-uncertainty compensation is applied. The `socSourceEvidence.reportedNominalCapacityAmpereHours` member carries the reported nominal-capacity evidence, not optional learned FCC; selected-profile calibration and installed-unit scaling require qualification. This capacity use does not add a third global BMS startup compatibility check. The owner-confirmed T2 centre-pack probe is the `Tcell` input for both current curves. MOS/T1 are not additional capability prerequisites. Measurement adequacy remains open.

Verification should exercise every temperature breakpoint and interpolation interval, voltage at and around the regenerative calibration members in [BatterySupervision.voltageDeratingCalibration](BatterySupervision.sysml), simultaneous restrictions (minimum, not multiplication), qualified zero, missing or invalid inputs, and preservation of independently qualified discharge and all other charge restrictions. A 17 Ah capacity gives 5.10 A base current only as an example.

## Discharge capability evidence

[REQ-SYS-BATSUP-012–015](BatterySupervision.sysml) use the same startup-captured standard nominal-capacity reference for the controller cycle to derive the discharge current ceiling. Apply the existing temperature and voltage curves to the qualified reported cell-temperature reading and the minimum of all fourteen qualified group-voltage readings, then select the smaller current ceiling. No numerical measurement-uncertainty compensation is applied. BatterySupervision publishes this selected operating discharge limit exactly as the minimum of its temperature and voltage curves, subject to the existing path-disabled, required-data qualification and retained-fault rules. A qualified disabled path contributes zero; missing required evidence leaves the branch unqualified with effective zero. BatterySupervision adds no generic physical/configuration current ceiling, runtime cap or settings input. Actual physical pack-current protection is configured and validated in the supplied BMS. Known disabled discharge path is qualified zero. The accepted temperature curve gives zero discharge ceiling at cell temperature ≤−5°C; owner disposition retains −10…+40°C E/E startup ambient and requires sufficiently warm cells for propulsion ([DEC-BAT-002](../../../../../Requirements/DEC-001_Decisions_and_Open_Issues.md#dec-bat-002), [OI-051](../../../../../../README.md#15-unresolved-issues)). Product validation shall check measurement adequacy and cutoff behavior; probe role, accuracy, coverage and response timing remain open.

Useful T-SW/T-SYS evidence covers each temperature breakpoint and interpolation interval, voltage at and around the discharge calibration members in [BatterySupervision.voltageDeratingCalibration](BatterySupervision.sysml), simultaneous restrictions (minimum, not multiplication), qualified zero, missing/invalid/unqualified capacity, temperature and any of 14 group voltages, disabled/unknown discharge-path state, and independent discharge/charge branch operation. A 16.75 Ah starting configuration gives 16.75 A base current only as an arithmetic example, not a qualified or aged capacity measurement.
