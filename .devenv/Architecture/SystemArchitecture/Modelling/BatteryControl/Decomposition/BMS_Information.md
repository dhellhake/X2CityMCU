# JBD UART interface definitions

This page records the selected interface's source facts, provenance, and qualification evidence. It is not a second software requirement catalogue: normative software behavior is defined by the BatterySupervision Abstract Software Requirements, especially [REQ-SYS-BMSIF-001..003 and 005..014](BatterySupervision.sysml). Those records own acceptance, rejection, qualification, source-timeliness assessment, retention, recovery, and timing obligations. REQ-SYS-BATSUP-001 owns the two per-startup checks (decoded software version 3.2 and reported series-group count 14), both from the same current accepted Basic (`0x03`) response. BMSIF-005/008 own basic-field scale and temperature/probe qualification, BMSIF-006 owns the fourteen group-voltage observations, and BATSUP-002..005 own operating-limit qualification, actual-SOC qualification and charge/discharge path capability. `0x05` identity remains informational; physical hardware/model/configuration acceptance is commissioning evidence. The values below describe the manufacturer protocol and remain subject to installed-unit qualification.

## Protocol facts

The selected pack and BMS facts, source hierarchy, and qualification status are maintained in [BAT-001](../../../../../Battery/BAT-001_Selected_Pack_and_BMS.md#fixed-inputs-and-provenance). The owner-confirmed unit is JBD SP14S004 hardware V1.0, firmware version 3.2, using UART. The earlier SP14S004P14S50A designation records provenance for the 14S50A selection, not an alternate device. BAT-001 cites the JBD universal UART protocol V12 as a generic manufacturer reference; the installed firmware version is known, but the fixed firmware-to-protocol mapping and response schemas still require captured installed-unit evidence. Do not infer installed-unit settings or capability from the family datasheet. Firmware version 3.2 is not proof of protocol revision or wire encoding.

### Wire format and source-level decoding facts

| Item | Manufacturer V12 source fact |
|---|---|
| Request frame | `DD A5 command length payload checksum 77` |
| Response frame | `DD command status length payload checksum 77` |
| Checksum | 16-bit two's-complement checksum over command/length/payload in a request and status/length/payload in a response. |
| Byte order | Multibyte values are high-byte first. |

| Read command | Source-described data and format |
|---|---|
| `0x03` basic information | Pack voltage, signed current, capacity/RSOC, reported version, balance/protection/FET status, series count, and temperature fields. Voltage scale is 10 mV. Current sign is positive for charging and negative for discharging. The FET-status scale bit selects 10 mA/10 mAh or 100 mA/100 mAh current/capacity scaling. Temperature conversion is `(raw - 2731) / 10` °C. Layouts and optional extensions depend on the supported firmware form. |
| `0x04` group voltages | High-byte-first group voltage values in mV; 14 groups occupy 28 payload bytes. Values represent the 14 series groups, each containing five parallel cells in the selected pack. |
| `0x05` identification | Device/version identification string. Length, encoding, and extension support require installed-unit evidence. Identity text alone does not describe effective configuration. |

These facts do not establish measurement accuracy, field presence, or applicability to a particular firmware layout. In particular, group voltage does not observe individual parallel cells; the family reference's one internal and one external temperature channel describes family capability, not installed-unit implementation or complete cell, motor, or inverter thermal coverage. Owner-reported app labels MOS, T1, and T2 and provisional roles/centre-probe placement are recorded in [BAT-001](../../../../../Battery/BAT-001_Selected_Pack_and_BMS.md#owner-reported-app-temperature-readings-2026-10-26); they do not establish UART count, index, order, encoding, or physical correspondence. Reported RSOC is an observation, not proof of actual SOC. See BAT-001 for the full limitations and distinct evidence status of owner reports, manufacturer ratings, and calculations.

The generic V12 basic-information FET-status mapping identifies bit 0 as charge-FET status and bit 1 as discharge-FET status; 1 means enabled and 0 means disabled. These are manufacturer protocol facts, not yet accepted decoding semantics for the installed hardware V1.0 / firmware 3.2. They do not prove physical current transfer or isolation. Keep this protocol mapping here; [REQ-SYS-BMSIF-005](BatterySupervision.sysml#req-sys-bmsif-005) requires qualification of the named observations against installed-unit evidence, and [REQ-SYS-BATSUP-004/005](BatterySupervision.sysml#req-sys-batsup-004) define how qualified states constrain capability.

### Verification guidance

Use the canonical requirements in [BatterySupervision.sysml](BatterySupervision.sysml) as the normative acceptance basis. The following evidence groups are a verification aid, not additional runtime requirements:

| Requirement group | Useful verification evidence |
|---|---|
| `REQ-SYS-BMSIF-003` | T-SW byte-exact response-envelope vectors for complete/unambiguous boundaries, start/end markers, declared versus actual byte length, protocol length bounds, checksum, truncation, and ambiguous concatenated framing. Responses that fail envelope conditions update no measurement and refresh no source timer. T-SYS captures selected-unit exchanges to establish response-envelope behavior. |
| `REQ-SYS-BMSIF-014` | T-SW/T-SYS cases combine envelope conditions with matching versus wrong outstanding requests and success versus non-success response status, including request deadlines. Only a response meeting the envelope conditions, matching the outstanding request, and reporting success may update measurements. A response with a valid envelope and non-success status is a transaction failure; preserve existing failure, timeout, and retention behavior. |
| `REQ-SYS-BMSIF-005..008` | T-SW schema/value vectors for exact per-command payload lengths, field counts, offsets and encoding, signed current and both scale modes, series count, 14 ordered groups, optional fields, temperature conversion, and installed-unit charge/discharge FET-state mapping. T-SYS verifies each field's decoded value, identity, and path-state interpretation against suitable independent references. Also demonstrate that mutually inconsistent but individually valid readings do not invalidate one another and that absent pack voltage does not affect qualification of a complete valid 14-group set. Record physical accuracy, uncertainty, and probe correspondence; independent-reference evidence supports commissioning and verification, not runtime agreement checks between BMS measurements. |
| `REQ-SYS-BMSIF-009..012` | T-SW cases exercise missing/unknown, invalid, and stale field conditions and verify affected fields remain unqualified while unrelated accepted fields retain qualification; specifically, SOC-field-only absence/invalidity/staleness withdraws only `StateOfCharge` qualification without affecting startup, limits, status or fault recognition; pack-current-field-only absence/invalidity/staleness withdraws only the existing `BatteryCurrent` value qualifier and does not change battery operating limits, BatteryStatus, actual SOC, or recognized-fault behavior. Contrast with loss of a whole Basic response or transport, where other fields follow their own age, qualification, and existing fault-recognition rules. Also cover private field timers, accepted same-value updates, unrelated/rejected frames, no-frame timeout, field-level loss, and retained observations. T-SYS covers controller startup/restart, BMS sleep/wake, delayed/missing replies, short communication interruption, source loss, timeout-driven qualification withdrawal and requalification. For the currently shared protection/path-state validity, verify loss or expiry leaves both named path observations unqualified; check published fields against the modeled observation interface and verify internal age/timer supervision drives timely qualification withdrawal. Verify display fallback cannot qualify control data, and requalification does not clear an assigned system fault latch. |
| `REQ-SYS-BATSUP-004/005` | T-SW/T-SYS crosses all four known charge/discharge enabled/disabled combinations, verifying a disabled path produces qualified zero only for its own branch. Verify enabled status leaves all remaining envelope constraints active and does not imply positive capability. Inject unknown/invalid/stale required path-state evidence and verify each dependent branch becomes unqualified at zero. Include recognized-fault cases to confirm existing fault evidence and system response remain effective. |
| `REQ-SYS-BMSIF-013` | T-SYS measures response, startup, polling, and recovery behavior against dependent-control reaction budgets and fitted/detached storage energy budgets. Record selected command order, deadlines, retry behavior, and derived thresholds as qualification results, not manufacturer defaults. |

T-SW is software-level vector and boundary verification; T-SYS is selected-unit/system integration evidence. Where appropriate, retain interface, analysis, and fault-injection evidence alongside them. Qualification evidence should include byte-exact exchanges for each implemented read, board/firmware/configuration identity, exact implemented response length/count/encoding, probe count and correspondence, reference instruments and uncertainty, and conditions of capture. A generic protocol example is not selected-unit evidence. Establish the fixed firmware-version-to-supported-schema mapping from accepted captures; do not infer it from version 3.2 or add generic extension discovery.

### Open qualification inputs

The following remain engineering inputs and evidence dependencies, not values specified by this page:

- Captured acceptance of installed board V1.0 and firmware 3.2, effective configuration identity; fixed firmware-to-protocol mapping; supported `0x03`/`0x05` lengths, field counts, offsets, and encodings; and UART temperature-field count/index/order/encoding and correspondence to the three reported app labels and physical probes. The app labels are observed; their semantic roles are owner assumptions, and the external probe is reported at pack centre. Board revision may need controlled commissioning evidence if it is not observable over UART.
- UART electrical compatibility and connection arrangement, response behavior, wake/recovery behavior, and whether communication affects sleep or storage consumption.
- Physical measurement accuracy, latency, uncertainty, applicable per-field physical-domain limits, and probe correspondence for each consumed field. Independent references may establish these engineering properties; do not derive runtime validity by comparing reported measurements with one another.
- Compiled per-field source-update timeout and per-consumer source-timeliness criteria, startup/requalification deadlines, command order, poll interval, transaction response deadline, timeout/publication/delivery/use-delay bounds, retry behavior, and resulting fitted/detached power budget.

Track these under `OI-041/061` and `WS-OI-018/019` with the related BAT-001 qualification inputs.

## Regenerative capability evidence

[REQ-SYS-BATSUP-007–011](BatterySupervision.sysml#req-sys-batsup-007) use qualified standard nominal full-pack capacity from Basic (`0x03`), the qualified reported cell-temperature reading directly and all fourteen qualified group-voltage readings to assess regenerative pack capability. The voltage input is their maximum; no numerical measurement-uncertainty compensation is applied. The `socSourceEvidence.reportedNominalCapacityAmpereHours` member carries the reported nominal-capacity evidence, not optional learned FCC; selected-profile calibration and installed-unit scaling require qualification. This capacity use does not add a third global BMS startup compatibility check. Probe roles and measurement adequacy remain open: MOS/T1 is not proven to represent cell temperature, and the external central T2 assignment is provisional.

Verification should exercise every temperature breakpoint and interpolation interval, voltage at and around the regenerative calibration members in [BatterySupervision.voltageDeratingCalibration](BatterySupervision.sysml#req-sys-batsup-016), simultaneous restrictions (minimum, not multiplication), qualified zero, missing or invalid inputs, and preservation of independently qualified discharge and all other charge restrictions. A 17 Ah capacity gives 5.10 A base current only as an example.

## Discharge capability evidence

[REQ-SYS-BATSUP-012–015](BatterySupervision.sysml#req-sys-batsup-012) use the same startup-captured standard nominal-capacity reference for the controller cycle to derive the discharge current ceiling. Apply the existing temperature and voltage curves to the qualified reported cell-temperature reading and the minimum of all fourteen qualified group-voltage readings, then select the smaller current ceiling. No numerical measurement-uncertainty compensation is applied. The published qualified discharge limit is the exact minimum of that computed pack ceiling and every other applicable qualified battery-side current ceiling or restriction; a qualified disabled/prohibited path contributes zero. A missing or unqualified required applicable constraint leaves the branch unqualified with effective zero, not omitted. With no other lower limit the computed pack ceiling is published; no arbitrary additional derating is permitted. Known disabled discharge path is qualified zero. The accepted temperature curve gives zero discharge ceiling at cell temperature ≤−5°C; owner disposition retains −10…+40°C E/E startup ambient and requires sufficiently warm cells for propulsion ([DEC-BAT-002](../../../../../Requirements/DEC-001_Decisions_and_Open_Issues.md#dec-bat-002), [OI-051](../../../../../../README.md#15-unresolved-issues)). Product validation shall check measurement adequacy and cutoff behavior; probe role, accuracy, coverage and response timing remain open.

Useful T-SW/T-SYS evidence covers each temperature breakpoint and interpolation interval, voltage at and around the discharge calibration members in [BatterySupervision.voltageDeratingCalibration](BatterySupervision.sysml#req-sys-batsup-016), simultaneous restrictions (minimum, not multiplication), qualified zero, missing/invalid/unqualified capacity, temperature and any of 14 group voltages, disabled/unknown discharge-path state, and independent discharge/charge branch operation. A 16.75 Ah starting configuration gives 16.75 A base current only as an arithmetic example, not a qualified or aged capacity measurement.
