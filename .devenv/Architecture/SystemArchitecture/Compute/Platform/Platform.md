# Platform
## Platform requirements

**Type:** Abstract Software Requirement. **Target:** `LE-PLATFORM`. **Status:** Draft.

These obligations allocate compute runtime initialization and validation/execution of RidingControl's sleep handoff to Platform. RidingControl alone determines sleep eligibility from current qualified Off and traction sleep-permission evidence. Platform does not consume or recheck those source records; it validates the current request's qualification, source context, lifetime and cancellation before execution. RidingControl also owns operation lifecycle, Ready, fault lifetime and riding authority.

| ID | Requirement | Derived from / governing contract | Planned verification / remaining gate |
|---|---|---|---|
| <a id="req-sys-plt-003"></a>`REQ-SYS-PLT-003` **Draft — 2026-10-05** | After each controller wake, Platform shall publish a current `ComputeRuntimeInitialization` record. It shall set `requiredRuntimeReady=true` only when the record qualifies current-context initialization and availability of the required runtime clocks, peripherals and runtime monotonic timebase; failed or incomplete initialization shall not be represented as ready. Calling tasks shall supply execution-time references sampled from that initialized timebase. This result shall not represent vehicle self-test completion, Ready, fault clearance or drive permission. | [REQ-SYS-STA-001](../../../../Requirements/System_Requirements/Power_Startup_and_Faults.md#req-sys-sta-001), [REQ-SYS-STA-006](../../../../Requirements/System_Requirements/Power_Startup_and_Faults.md#req-sys-sta-006), [REQ-SYS-HSI-002](../../../../Requirements/System_Requirements/System_Hardware_Software_Interface.md#req-sys-hsi-002), [REQ-SYS-PLT-002](../../../../Requirements/Abstract_Software_Requirements/System_Interface_Allocations.md#req-sys-plt-002). | `T-SW`, `T-FI`, `T-SYS`: after each wake, verify `requiredRuntimeReady` is true only with current qualified evidence for each required runtime resource and monotonic timebase; distinguish qualified false from unavailable/invalid qualification. Verify caller-supplied execution-time references use that current timebase. Inject failed, incomplete and context-mismatched resources. Vehicle self-tests and the common Ready guard remain separately verified. |
| <a id="req-sys-plt-005"></a>`REQ-SYS-PLT-005` **Draft — 2026-10-05** | At actual sleep entry, Platform shall validate that the Session `ComputeSleepRequest` with `enterSleep=true` is the latest current qualified grant, its source context is valid for the current Session context, and its `expiry` has not elapsed. The true handoff shall preserve the grant's qualification, source context and `expiry` without renewal. An absent, invalid, expired, context-mismatched, false, cancelled or superseded request shall not initiate sleep; Platform shall clear any pending true handoff and keep the controller awake. | [REQ-SYS-CTL-006](../../../../Requirements/Abstract_Software_Requirements/Settings_and_Control_Policy.md#req-sys-ctl-006), [REQ-SYS-PWR-003](../../../../Requirements/System_Requirements/Power_Startup_and_Faults.md#req-sys-pwr-003); `ComputeSleepRequest`. | `T-SW`, `T-FI`, `T-SYS`: validate qualified latest grants; attempt entry for absent, invalid, expired, context-mismatched, false, cancelled and superseded requests; verify handoff preserves Session qualification, source context and expiry without renewal, and no invalidated grant can initiate sleep. Revoke/expiry during a pending handoff must be tested against actual entry. Numeric lifetime and finite race/order/transport behavior remain downstream derivation and qualification gates. Physical inhibition, residual/generated energy and component acceptance remain under `REQ-SYS-ENE-002/003`. |
