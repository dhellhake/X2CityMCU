# Charging session policy

**Type:** Abstract Software Requirement. **Target:** [LE-CHARGE-POLICY](../../Architecture/ARCH-001_System_Architecture.md#le-charge-policy), realized by **SC-CHARGE-POLICY** within LE-CHARGE. Part of **REQ-001-R1.6**; [model and shared verification](../REQ-001_Requirements.md).

This leaf owns session-state interpretation, charge-enable intent and four logical indication modes. Source/connection qualification, physical charging/protection, charging-activity evidence and visible indication remain System responsibilities. Its deployment must support removed-pack charging without powered vehicle electronics; host and state-retention realization remain open.

## State and event contract

Keep session status (initial need unqualified / eligible incomplete / completed), qualification of retained state, fresh-check status, current fault inhibition, charging-condition validity and actual charging-activity evidence distinct. Initial need refers to SOC at the qualifying connection/power event, not an arbitrary later reading. Unknown initial need is neither a charge deficit nor evidence of an initially full battery. Current charging conditions and fault observations are reevaluated after every relevant event.

| Event / guard | Required policy effect |
|---|---|
| Physical charging connection/reconnection or qualified USB power restoration after interruption | Open a new initial-need assessment and required fresh checks. Qualify SOC at that event: below 80% gives eligible incomplete; at/above 80% gives completed; unknown remains unqualified. A prior fault still needs CHG-009 recovery unless a controller restart also occurs. |
| Late initial-SOC qualification | Resolve only from evidence valid for the original event, including intervening change/uncertainty. A later SOC decline alone cannot create initial eligibility. |
| Ordinary cold/healthy-too-warm waiting or temporary source interruption | Interruption alone retains session/completion. Withhold charge intent while conditions are unsuitable; only a qualifying restoration/new connection opens a new-session assessment. Resume an eligible incomplete session automatically once conditions and required checks permit. |
| Qualified completion | Set completion hold and withdraw charge intent. Completion criteria include the conservative 80% ceiling; no exact cell voltage or extra minimum charge deficit is introduced. |
| Completed, then SOC decreases with connection and USB power uninterrupted | Retain completion; no top-up. Warming or cooling, source-contract changes and returned telemetry alone do not reopen the session. |
| Actual charging fault recognized, in any phase | Inhibit charge and select Fault. Mere physical clearance retains the current-execution fault inhibition. |
| Qualifying recovery event with CHG-009 fresh checks/conditions satisfied | Clear current fault inhibition; charge intent still depends on qualified incomplete eligibility and current permissives. Full/completed state cannot be bypassed or require positive charging merely to prove recovery. |
| Unexpected charging-controller restart without a new-session event | Discard old fault history/indication; withhold intent and show Waiting during fresh checks, unless a new fault is recognized. Preserve and qualify prior completion/initial eligibility; restart itself cannot create a new initial-need assessment. |
| BMS reset, wake or telemetry return alone | Preserve session/completion/fault state. Requalify affected observations; withhold intent if required conditions are unqualified. Returned packets alone cannot clear inhibition. |
| Shared new-session event and controller reset | Apply both event effects: use the new session's initial assessment, discard old controller fault history and require fresh checks. Retention through reset cannot override a genuine new connection/power event. |

Charge intent is true only when state is qualified eligible-incomplete, required checks have passed, current conditions permit charging and no fault inhibits it. Accepted intent is not proof of actual transfer; physical response must meet the parent requirements even when policy execution or communication fails.

| Indication priority while indication is powered | Logical mode |
|---|---|
| Current-execution fault inhibition / newly recognized fault | Fault |
| No current fault, fresh checks or retained-state qualification pending | Waiting |
| Checks/state qualified and completion hold present | Completed |
| Permitted charge intent and qualified active charging | Charging |
| Remaining cases, including unqualified initial need or ordinary waiting | Waiting |

Charging-activity evidence is a separately qualified System input; permitted intent with unqualified activity cannot select Charging and falls to Waiting unless a higher-priority mode applies. Qualified activity may describe regulation/pulsed operation; it is not a chosen instantaneous-current test. Failed state continuity or required feedback follows its derived diagnostic criteria, with no charge authorized from unknown state. Current fault recognition overrides completion/waiting indication without erasing completion hold. No indication through an unavailable power supply is implied.
