# Detailed-design interface allocations

**Draft successor — 2026-09-18; retains REQ-001-R2.0.** Retained rows keep their released bodies; the later Draft regular-DMA/Hall, caller-time, fast-runtime and compile-time-calibration refinements are controlled successors. These downstream Abstract Software Requirements refine released System/HSI parents and the explicit SW realization allocation in ARCH-003.

## Caller-supplied execution-time allocation

`REQ-SYS-PLT-002` is the Draft successor allocation for the common `ExecutionTime { currentTimeMicroseconds: Integer }` input. Every dispatched project-host component invocation — `SC-SET.V`, `SC-SESSION.V`, `SC-DEMAND.V`, `SC-HMI.V`, `SC-LIGHT-POLICY.V`, `SC-ANALOG-ACQ.V`, `SC-ACCELERATOR-IF.V`, `SC-BRAKE-IF.V`, `SC-TEMPERATURE-IF.V`, `SC-SUPPLY-IF.V`, `SC-MOTOR-PHASE-IF.V`, `SC-HALL-IF.V`, `SC-TRACTION-CTRL.V`, `SC-BMS-LINK.V`, `SC-BAT-POLICY.V`, `SC-SERVICE-INFO.V` and `SC-PLATFORM.V` — and every standalone project-unit invocation receives `executionTimeIn` from its immediate caller. A nested unit within one bounded component invocation receives the component's fixed reference forwarded by that caller; it does not independently sample or read a clock. `SC-BMS` and `SC-VD18MT` are supplied opaque components and are excluded. The caller samples the one host-boot monotonic microsecond domain immediately before each dispatched component or standalone-unit invocation and passes that fixed live value; it shall not reuse that snapshot for another invocation. A planned release time, an earlier task-start snapshot or a component clock-service read is not an execution-time input. The caller and the invoked component shall retain the current reset generation with the invocation/context; reset creates a new generation without changing the one-domain rule.

Where an input needs an elapsed-validity, expiry or timeout decision, its receiving component owns the private per-input rule and evaluates it against `currentTimeMicroseconds` supplied through `executionTimeIn`. The guard shall conservatively account for the maximum elapsed interval from that snapshot through the relevant use or effect, including remaining bounded execution. For such an input, initial, invalid, unavailable or expired evidence is unavailable. A newly acquired valid measurement refreshes that measurement's timer even when its value is unchanged; a health-only or composite republication does not. Dequeuing an old record does not make it current. Retained settings, retained light requests, each component's immutable compiled calibration parameters and current context retain their parent-defined lifecycle and are not made periodically invalid solely by this allocation. Transport delay, consumer period, bounded invocation time/WCET and the applicable timeout shall meet the end-to-end bound. This allocation does not impose a transmitted generic freshness field: retain actual measurement/acquisition and event times, authority/command decision and expiry times, and their meaningful `*Microseconds` names wherever age or ordering matters.
