# Service information

**Type:** Abstract Software Requirement. **Target:** [LE-SERVICE-INFO](../../Architecture/ARCH-001_System_Architecture.md#le-service-info), realized by **SC-SERVICE-INFO** within LE-SERVICE. Part of **REQ-001-R1.6**; [model and shared verification](../REQ-001_Requirements.md).

This leaf assembles current diagnostic information for service. It consumes qualified observations and existing policy states; it neither performs every diagnostic nor grants operating permission. Physical access, diagnostic tools, configuration writes, isolation and final software hosting remain separate responsibilities.

## Information contract

The applicable service task determines the required observations under the [system service contract](../System_Requirements/Service_and_Durability.md#service-acceptance-contract). Missing sources cannot be substituted with data from an earlier controller execution. Context identifies the relevant producer/session; it does not prescribe a timestamp, counter or persistent store. A service-readout restart alone is not a riding/charging-controller restart and cannot release inhibition in an unaffected domain; fresh observations from that domain may still report its existing current-session fault.

| Information group | Meaning preserved at the service boundary |
|---|---|
| Identity/configuration | Available actual component/firmware identity and effective configuration/calibration identity; separate requested settings and qualified correspondence. BMS configuration readback follows the selected-unit capability, not assumed vendor commands. |
| Qualification and faults | Current check completion/results and diagnostic validity; current recognized conditions, retained inhibition/restriction reasons and selected HMI or charging mode remain separate. Report selection must not conceal other current diagnostic observations from service. |
| Rider/settings/motion | Qualified pedal/brake/speed/direction/rest information and current-startup receipt versus active/pending settings, as required for the task. No fixed service setting replaces the VD18MT choice. |
| Battery and power | Required qualified SOC, group/pack voltages, signed current, temperatures and path/protection observations. Keep actual SOC separate from usable-charge display and unavailable current separate from its HMI 0 A fallback. |
| Output | Command/permission versus qualified actual torque/braking/charging information; unknown physical state remains unknown. Neither a zero command nor a BMS path-status bit establishes isolation. |
| Charging session | Existing initial eligibility, completion hold, fresh-check status, current fault inhibition and logical indication; observe each domain's reset rules without manufacturing a new-session event. |

No new rider indication, automatic parameter-writing facility or persistent fault logger is allocated. Interface electrical effects, polling load and execution timing require system acceptance; software presentation cannot qualify its own source measurement or protective action.
