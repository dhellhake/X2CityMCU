# Session fault-report policy

**Type:** System Requirement. **Target:** `LE-SESSION`. These retained approved HMI report-policy requirements are Session obligations; HMIControl encodes and transmits the report it receives without changing selection, priority, or retention.

| ID | Requirement | Planned verification / distinguishing cases | Sources | Open dependencies / qualifications |
| --- | --- | --- | --- | --- |
| <a id="req-veh-hmi-006"></a>`REQ-VEH-HMI-006` | A selected indication of a problem requiring fixing shall remain for the session despite condition clearance and report whenever communication permits. Every restart shall discard old selection and report newly recognized faults independently of Ready. | `I`, `T-SYS`, `T-FI`. H: accelerator first, brake later, accelerator repaired, restart with only brake faulty → new 0x0D. Cover converse and each grouped category persisting alone. | [DEC-FLT-003](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-003), [DEC-FLT-004](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-004), [DEC-FLT-006](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-006), [DEC-FLT-008](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-008), [DEC-FLT-002](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-002), [DEC-STA-001](../DEC-001_Decisions_and_Open_Issues.md#dec-sta-001) | `WS-OI-007`, `WS-OI-008`, `WS-OI-009`, `WS-OI-010`, `WS-OI-012`, `WS-OI-018`, `WS-OI-019`: Report reset does not enable torque; ordinary startup qualification alone is not a recognized fault. |
| <a id="req-veh-hmi-007"></a>`REQ-VEH-HMI-007` | Within a session, the first detected accelerator 0x0A, brake 0x0D, speed 0x03, battery 0x07, temperature-limit 0x06, blocked-motor 0x04 or generic 0x05 fault shall remain the selected report from that group, without replacement/alternation by later group faults. | `I`, `T-SYS`, `T-FI`. H: ordered combinations of all seven categories, first condition clearing before/after later faults, and indistinguishable order under [REQ-VEH-HMI-018](#req-veh-hmi-018). | [DEC-FLT-003](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-003), [DEC-FLT-004](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-004), [DEC-FLT-006](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-006), [DEC-FLT-008](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-008) | `WS-OI-001`, `WS-OI-008`, `WS-OI-009`, `WS-OI-010`, `WS-OI-012`, `WS-OI-015`, `WS-OI-018`, `WS-OI-019`: All seven outrank 0x01; approved [REQ-SYS-CTL-004](../Abstract_Software_Requirements/Settings_and_Control_Policy.md#req-sys-ctl-004) specifies the lowest code only for indistinguishable earliest ties; recognition timing remains open. |
| <a id="req-veh-hmi-009"></a>`REQ-VEH-HMI-009` | Low-charge warning shall activate at/below 20% actual SOC using `0x01` when selected/communicable, and clear automatically only above 20%, without restart. | `I`, `T-SYS`. B/H: startup low, cross 20%, reach 10%, recover to exactly/above 20%. Clear while masked by a retained fault; no stale warning may reappear later. | [DEC-SOC-001](../DEC-001_Decisions_and_Open_Issues.md#dec-soc-001) | `WS-OI-005`, `WS-OI-008`, `WS-OI-009`, `WS-OI-010`, `WS-OI-017`: With no remaining report use the no-error value. Project low charge is not a measured voltage fault or a requirement for the separate undervoltage status bit. |
| <a id="req-veh-hmi-010"></a>`REQ-VEH-HMI-010` | The selected [REQ-VEH-HMI-007](#req-veh-hmi-007) group report shall outrank low-charge `0x01` regardless of detection order, preserving its restart-based lifetime. | `I`, `T-SYS`, `T-FI`. H: both orders for every grouped category; clearing charge cannot clear retained fault. After restart, current qualified SOC determines 0x01 if no higher report. | [DEC-SOC-001](../DEC-001_Decisions_and_Open_Issues.md#dec-soc-001), [DEC-FLT-003](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-003), [DEC-FLT-006](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-006), [DEC-FLT-008](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-008) | `WS-OI-007`, `WS-OI-008`, `WS-OI-009`, `WS-OI-010`, `WS-OI-017`, `WS-OI-018`, `WS-OI-019`: All seven categories, including 0x04/0x05, use the same priority over 0x01. |
| <a id="req-veh-hmi-014"></a>`REQ-VEH-HMI-014` | Temperature indication shall remain for the session after normalization, reporting `0x06` when selected/communicable; every restart shall assess it afresh. | `I`, `T-SYS`, `T-FI`. H/F: normalize without restart; normal/unexpected restart with temperature normal versus persistent/new violation. | [DEC-TMP-001](../DEC-001_Decisions_and_Open_Issues.md#dec-tmp-001) | `WS-OI-007`, `WS-OI-008`, `WS-OI-009`, `WS-OI-010`, `WS-OI-019`: Retained report does not itself force auxiliary shutdown. |
| <a id="req-veh-hmi-018"></a>`REQ-VEH-HMI-018` | Indistinguishably ordered reportable faults shall select one tied fault by a consistent rule and retain selection until restart under the applicable reporting rules. | `I`, `T-SYS`, `T-FI`. Repeat equivalent ties; compare distinguishably ordered faults, subsequent faults and condition clearance. | [DEC-FLT-008](../DEC-001_Decisions_and_Open_Issues.md#dec-flt-008) | `WS-OI-008`, `WS-OI-009`, `WS-OI-010`, `WS-OI-019`: approved [REQ-SYS-CTL-004](../Abstract_Software_Requirements/Settings_and_Control_Policy.md#req-sys-ctl-004) specifies the tie rule; detection-order resolution remains open; a tie rule does not override priority between categories. |
