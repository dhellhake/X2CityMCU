# System hardware/software interface

**Status:** Released clarification in REQ-001-R2.0. The approved rows below retain their released bodies; the Hall-sensored FOC allocation note does not alter a requirement target. **Type:** System Requirement. The requirements in this cluster target the named logical leaf; a later design allocation may identify its HC/SC realization but does not change the requirement target. This document defines semantic contracts at hardware/software boundaries. It neither selects a final controller, connector/pinout, rail, numeric timing value, protection topology or BMS configuration write.

Each endpoint transaction or observation carries its producer identity, configuration, reset/power context, semantic value, qualification state and freshness/source-age evidence.  A raw level, successful transfer, command acceptance, status bit or prior value does not by itself establish physical validity, output, energy isolation or authorization.  Quantitative electrical, timing, uncertainty, diagnostic-coverage and environmental acceptance is a later gate.

## Hall-sensored FOC realization allocation note

[MCD-001](../../Motor/MCD-001_Hall_Sensored_FOC_Technical_Design.md) selects Hall-sensored FOC below the unchanged HSI-001/004 contracts. HC-INPUT-FE and SC-ANALOG-ACQ provide raw acquisition; SC-HALL-IF provides qualified calibrated/aligned electrical position; HC-TRACTION-POWER and SC-MOTOR-PHASE-IF provide qualified phase-current feedback; and SC-SUPPLY-IF provides qualified fast local DC-link voltage. SC-TRACTION-CTRL receives those records for bounded current/vector control and separate actual-output/energy observation. SC-PLATFORM supplies static resource/rank/trigger configuration, calibration lifecycle and the fast-inhibition bridge; SC-SESSION alone owns riding-session fault latch/report policy. BMS UART information is a battery-policy input and is not the fast current-loop DC-link observation. These are approved realization allocations, not a claim that a requested `Iq`, PWM state or BMS packet proves torque, braking, physical zero or energy direction.

## Interface acceptance ledger

The confirmed facts are the passive coded brake network, the VD18MT five-pin 5 V-class UART and its protocol reference, the selected JBD BMS/UART protocol basis and the built battery. The owner-selected, unmodified DRV8300DRGE-EVM is the traction-board baseline under its [project integration record](../../Architecture/DRV8300DRGE-EVM/DRV8300DRGE-EVM_Integration_and_Requirements_Fit.md); its actual revision/jumper positions, host/adapter, power tree, endpoint allocation and vehicle electrical acceptance remain open. The owner-selected WeAct STM32H723VGT6 V1.2 is the vehicle `HC-CONTROLLER` under the [allocated traction HSI](../../Architecture/DRV8300DRGE-EVM/DRV8300DRGE-EVM_WeAct_STM32H723VGT6_Traction_HSI.md); its pin matrix, power path, adapter, endpoint allocation and vehicle electrical acceptance remain open. The endpoint requirements below refine this system contract without duplicating their parent behavioral requirements.

| Boundary | Producer → consumer | Required state at startup/off/fault | Later gate |
|---|---|---|---|
| Rider/input | supplied device/acquisition → input qualification → riding consumers | Unknown until current-context qualification; no stale prerequisite evidence | Electrical envelopes, sensing, freshness/skew and fault coverage |
| VD18MT | display ↔ HMI adapter | No inferred received selection; report transmission is not receipt confirmation | Selected-unit electrical/transport/power-off and presentation characterization |
| BMS | vendor BMS → one active vehicle endpoint | BMS reset/packet return requalifies data only | Actual board firmware/configuration, isolation/reference/protection and scaling |
| Traction/lamp | policy → physical realization → output observation | Command intent is not output; required conservative lamp behavior precedes policy readiness | Actuator/lamp interface, actual-output reference and response/protection evidence |
| Service | producers → service information → maintainer | Reports preserve producer/reset context and cannot grant authority | Access, isolation, schema/coherence and permitted task acceptance |
