# STM32H723VGT6 V1.2 with LCD — 550 MHz validation, 2026-09-13

The firmware initializes the owner-confirmed WeAct V1.2 STM32H723VGT6 board
with its fitted 0.96 inch 80x160 ST7735 LCD at the specified 550 MHz CPU
maximum. Debug and release images passed Atmel-ICE target tests. The LCD
population is documented; display rendering and backlight control remain
unimplemented.

The [official WeAct V1.2 schematic](https://github.com/WeActStudio/WeActStudio.MiniSTM32H723/blob/0a08d2808291a7ff38c8a4f89748693019257345/Hardware/STM32H7xx%20SchDoc%20V12.pdf)
controls board wiring. ST [DS13313 Rev. 5](https://www.st.com/resource/en/datasheet/stm32h723vg.pdf)
and [RM0468 Rev. 3](https://www.st.com/resource/en/reference_manual/dm00603761.pdf)
control the clock, power, memory and watchdog constraints.

The clock uses HSE 25 MHz / M=5 × N=110 / P=1. PLL input is 5 MHz and
wide-VCO output is 550 MHz, within the 192–836 MHz range. CPU/SYSCLK is
550 MHz, AXI/AHB is 275 MHz, and APB1–4 are 137.5 MHz. VOS0 and Flash
latency 3 / `WRHIGHFREQ=3` are established before switching to PLL1.

ST requires `CPU_FREQ_BOOST` above 520 MHz. This persistent option disables
ITCM/DTCM ECC. The [provisioning script](../../STM32H723VGT6/enable-550mhz.gdb)
sets only `FLASH_OPTSR2` bit 2. Firmware enables the SYSCFG clock and checks
the runtime mirror in `SYSCFG_UR18` bit 0 while still using HSI; absent boost
prevents the 550 MHz switch. Firmware does not program option bytes at boot.

The [provisioning log](2026-09-13-stm32h723-boost.log) records:

| Register | Before | After |
| --- | --- | --- |
| `FLASH_OPTSR2_CUR` / `_PRG` | `0x00000000` | `0x00000004` |
| `FLASH_OPTSR_CUR` / `_PRG` | `0x0306aad0` | `0x0306aad0` |
| `SYSCFG_UR18` | Boost disabled | `0x00000001` after reset |

Other option bits, including the default shared AXI/ITCM allocation, were
preserved. The earlier 480 MHz implementation used a 960 MHz VCO outside the
H723 limit; that configuration is superseded. Its historical observations are
retained in the [migration record](2026-09-12-stm32h723-migration.md).

## Firmware validation

`cargo build` and `cargo build --release --config profile.release.debug=2`
passed. Compile-time SysTick checks cover 550 ticks per microsecond and the
24-bit interval boundary: 30,504 microseconds fits, 30,505 exceeds it.

WWDG1 uses PCLK3 / 32768, reload `0x7F`, window `0x61`. Strict `T < W`
requires 31 decrements before refresh (7.387695 ms nominal); reset follows
64 decrements (15.252015 ms nominal). Prescaler phase can shorten an interval
by one tick. The software interval is 8.5–14.0 ms, and compile-time checks use
the conservative 63-tick earliest reset boundary of 15.013702 ms.

The [smoke test](../../STM32H723VGT6/smoke-test.gdb) programs Flash, compares
loadable sections, resets, soaks for 30 seconds, checks configuration and task
state, then verifies missing-service watchdog reset/recovery and PE3 toggling.

## Debugger RAM preservation regression

An additional live Flash comparison exposed a debugger configuration defect.
The upstream STM32H7 OpenOCD configuration uses `0x20000000` as a temporary
work area with RAM backup disabled. Its CRC algorithm overwrote this firmware's
relocated DTCM vectors. Resuming without reset then produced a HardFault at
`0x5d11e00c`; the CRC instruction word written over the HardFault vector was
exactly `0x5d11e00d`. This is recorded in the [initial failed live check](2026-09-13-stm32h723-550mhz-final.log)
and the [controlled reproduction](2026-09-13-stm32h723-550mhz-crc-diagnosis.log).
A reset reconstructed the vectors and a [recovery soak](2026-09-13-stm32h723-550mhz-recovery.log)
passed with 3024 PFM cycles and no fault.

The board OpenOCD configuration now sets `-work-area-backup 1`, preserving
temporary algorithm allocations. The [live-image regression](../../STM32H723VGT6/verify-live-image.gdb)
then compared all six Flash sections, preserved the full 64 KiB DTCM work area,
and resumed scheduling for another 30 seconds without fault; see the
[passing log](2026-09-13-stm32h723-550mhz-live-verify.log). Both before/after RAM
snapshots had SHA-256 `2AC13532F3355BEE39D3AEF409E81747BC54F0FF79763DB869F682D9D78A3E22`.

The complete release flash/program/compare/30-second-soak/watchdog/heartbeat
campaign was then repeated with the corrected OpenOCD configuration and passed;
see the [final release log](2026-09-13-stm32h723-550mhz-release-final.log).
The release firmware was resumed, GDB detached, and OpenOCD shut down through
its control socket. The board was left running the 550 MHz release image.

## Limits

The register checks and host-timed soaks establish configured clock ratios and
continued execution, not calibrated oscillator frequency, scheduler drift or
worst-case execution timing. Connector-level UART baud/loopback/error behavior,
the complete PFM fault matrix, precise watchdog reset latency, and the SysTick
4096-tick WCET bound remain unmeasured. The fitted LCD is not initialized or
render-tested. Physical pin continuity was not measured. Boost's TCM ECC
disablement must remain part of the controlled configuration.
